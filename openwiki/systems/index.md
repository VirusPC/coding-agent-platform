# Files

- [Agent Implementations](agent-implementations.md) - How the six per-CLI agent wrappers in lib/sandbox/agents/ (claude, codex, copilot, cursor, gemini, opencode) install their CLI, configure authentication, attach MCP servers, stream output back to the UI, capture a session ID for follow-up turns, and report an AgentExecutionResult.
- [AI Content Generation (Branch Names, Commit Messages, Titles)](ai-content-generation.md) - The three AI SDK 5 generators in lib/utils/ — branch-name, commit-message, and task-title — that turn a raw user prompt into the git branch, commit message, and short title persisted on a tasks row, plus the deterministic fallback functions and the after()-based non-blocking dispatch from POST /api/tasks and POST /api/tasks/[taskId]/continue.
- [API Keys Management](api-keys-management.md) - Per-user encrypted provider API keys (anthropic, openai, cursor, gemini, aigateway) backed by the keys table, the GET/POST/DELETE surface at /api/api-keys, the readiness check at /api/api-keys/check, the system-env fallback in getUserApiKeys()/getUserApiKey(), and the API Keys dialog UI used to save or clear them.
- [Auth API Surface](auth-flow.md) - The HTTP routes under app/api/auth/ that drive sign-in (GitHub, Vercel), callback, session info, rate-limit, GitHub status, GitHub disconnect, and sign-out, plus the client-side hooks that call them and the three GitHub cookie sets they read.
- [Client State (Jotai, Cookies, Hooks)](client-state.md) - Client-side state model covering the Jotai atom store, the js-cookie preference utility, and the useTask polling hook that powers the task page.
- [Connectors (MCP Servers)](connectors-mcp.md) - User-owned Model Context Protocol server definitions stored in the connectors table, surfaced through the /api/connectors GET route, mutated by four server actions (createConnector, updateConnector, toggleConnectorStatus, deleteConnector), managed from the manage-connectors UI, decrypted at task-run time, and injected into each per-CLI agent's MCP configuration.
- [Database Schema (Drizzle + Postgres)](database-schema.md) - The seven PostgreSQL tables declared in lib/db/schema.ts (users, accounts, tasks, task_messages, connectors, keys, settings), their field semantics, foreign-key cascade behavior, unique indexes, encrypted columns, paired Zod insert/select validators, and the legacy userConnections / UserConnection aliases kept for the accounts rename.
- [GitHub Integration (Octokit & PR Workflow)](github-integration.md) - How the codebase talks to GitHub - the getOctokit() factory, the two-tier getUserGitHubToken() lookup, repository browser tabs, PR create/merge/close/reopen/sync endpoints, and the repository management routes.
- [Live Editor Surface (File Browser, Editor, Diff, Terminal, LSP)](live-editor-surface.md) - The client-side components and server-side API routes that make up the in-sandbox editor experience — file-browser, file-editor (Monaco), file-diff-viewer, terminal, autocomplete, and the LSP bridge — and how every server route reconnects to the kept-alive sandbox via Sandbox.get().
- [Sandbox Orchestration](sandbox-orchestration.md) - The modules under lib/sandbox/ that wrap the @vercel/sandbox SDK — createSandbox() as the canonical builder, the runCommandInSandbox / runInProject / runStreamingCommandInSandbox helpers, package-manager detection, port detection via Octokit, the git push / shutdown helpers, and the in-memory sandbox registry used inside a single serverless execution.
- [Task API Surface](task-api.md) - Every HTTP route under /api/tasks — the lifecycle collection endpoints, the per-task GET/PATCH/DELETE, the execution-control routes that drive the Vercel Sandbox, the GitHub PR and deployment routes, and the live-editor routes that back the file browser, Monaco editor, terminal, and LSP bridge — including the shared auth/ownership preamble, the reconnect preamble, the keepAlive gating, and the status-code conventions.
