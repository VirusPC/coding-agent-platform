# Files

- [Add an MCP Server](add-mcp-server.md) - End-to-end walkthrough of configuring a connector (preset or custom, local STDIO or remote HTTP/SSE), persisting it through the createConnector server action with AES-256-CBC encryption, and seeing it injected into the Claude or Copilot CLI at agent-run time via claude mcp add or --additional-mcp-config.
- [Connect GitHub to a Vercel-Signed-In User](connect-github.md) - The secondary GitHub connect flow — a user who is already authenticated with Vercel attaches a GitHub account by hitting GET /api/auth/github/signin, the callback's authMode=connect branch writes an encrypted token to the accounts table, and getUserGitHubToken then serves the linked token to every GitHub API route and the agent dispatcher.
- [Create and Run a Task](create-and-run-task.md) - End-to-end happy path from the user typing a prompt into the task form, through POST /api/tasks persisting a pending row, three parallel next/server after() callbacks (AI branch name, AI title, and the worker), createSandbox spawning a Vercel Sandbox, executeAgentInSandbox dispatching to a CLI, pushChangesToBranch pushing the commit, and the React client polling GET /api/tasks/:taskId to render the live status.
- [Follow-up Messages and Keep-Alive](follow-up-and-keep-alive.md) - How a user continues a completed, stopped, or errored task by sending a follow-up message — the POST /api/tasks/:taskId/continue route, the Sandbox.get() reconnect that preserves the existing VM when keepAlive is on, the start-sandbox/stop-sandbox pair that lets the user rehydrate or tear down the kept-alive sandbox, the PATCH stop action that flips status to stopped and kills the sandbox, and how every follow-up counts against the daily rate limit.
- [Open, Review, and Merge a Pull Request](open-pull-request.md) - End-to-end walkthrough of the PR lifecycle for a task — from a pushed branch and `status='completed'` row, through CreatePRDialog → POST /api/tasks/:taskId/pr (Octokit pulls.create), the task UI surfacing the PR with status badges and check-run indicators, MergePRDialog → POST /api/tasks/:taskId/merge-pr (squash-merge default, sandbox teardown, completedAt, prStatus='merged'), and the close/reopen/sync/sync-changes siblings that round out the lifecycle.
